FINDINGS
--------

[ADVISORY A1] tests/test_dca_signal.py lines 404–418 — I18 test is idempotency, not true T1

  The spec requires: "appending one extra row after as_of_date does not change output."
  The test calls compute_leaps_dca_signal(pd_obj, 'VTI', as_of) twice on the same
  pd_obj where as_of = index[-2] (one row before the end). Both calls see the same
  data — there is no second PriceData with an appended row. This validates that the
  function is deterministic, not that the [:as_of_date] slice excludes future data.

  A stronger I18 test would:
    1. Build pd_obj_short truncated at as_of_date.
    2. Build pd_obj_long with one additional row appended after as_of_date.
    3. Assert signal from pd_obj_short == signal from pd_obj_long at as_of_date.

  The T1 slice is implemented correctly (line 253: close_all = pd_obj.prices[ticker].loc[:as_of_date])
  but the test does not strictly verify it. This is advisory since the implementation
  is correct; the test weakness would only matter if a regression removed the [:as_of_date] slice.

[ADVISORY A2] dca_signal.py line 173 — price_data: object type annotation

  The function signature uses `price_data: object` with a `type: ignore[assignment]`
  cast at line 233 to avoid a circular import with data.py. This circumvents mypy's
  strict mode for this argument and hides any type error on the caller side.

  Preferred resolution: use TYPE_CHECKING guard or a Protocol to avoid the circular import
  while retaining type safety. As-is, mypy does not enforce that callers pass PriceData.

  No behavioural defect; advisory only.

[ADVISORY A3] dca_signal.py lines 381–384 — O(n²) lookback gate loop

  The gate series for the percentile distribution is computed via a Python for-loop
  with iloc slicing (lines 381–384), which is O(n²) for the lookback window. Spec
  acknowledges this as R-009 ("Acceptable for 5-year daily series ~1250 rows").
  No action required; flagged for awareness.

[ADVISORY A4] dca_signal.py line 288 — 1 uncovered line (vol_col fallback branch)

  Coverage report shows line 288 uncovered. This is the inner else-branch of the
  ASSET_VOL_INDEX resolution block. The exact scenario: ticker IS in ASSET_VOL_INDEX
  (so mapped_index is not None), but the expected iv_col_name (e.g. "VTI_IV") is
  absent from vol_prices.columns (line 282 evaluates False → vol_col stays None →
  control reaches line 284 fallback). The existing test_raises_on_missing_vol_prices
  reaches ValueError via the empty vol_prices path but misses this specific sub-branch.

  No behavioural defect; the end result (ValueError) is the same.
  A targeted test using vol_prices with a mismatched column name would achieve 100%.
