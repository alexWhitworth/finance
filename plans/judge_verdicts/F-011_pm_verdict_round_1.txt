B1  [BLOCKING]  I3 conservation violated when holdings contains tickers absent
    from target_weights.

    File: src/finance/portfolio_manager.py, lines 325–356
    Reproduce:
        lp = LivePortfolio(
            holdings={'VTI': 70_000.0, 'EXTRA': 30_000.0},
            target_weights={'VTI': 1.0},
            ...
        )
        nb = compute_nav_breakdown(lp)
        plan = compute_rebalance_plan(lp, nb, RebalanceRule.QUARTERLY,
                                      is_rebal_date=True, is_month_end=False)
        sum(t.trade_amount for t in plan.trades)  # → 30_000.0, not 0.0

    Root cause: `base_target_keys` iterates over target_weights keys only.
    A holding in `holdings` that has no corresponding key in `target_weights`
    (e.g. a residual position being wound down) is excluded from the order
    list. The target_values for the listed tickers sum to `base_nav` (all
    holdings including the stray), but current_values only sum to the listed
    holdings. Cash is created from thin air.

    Fix: Either (a) add a sell-all order for tickers in holdings not in
    base_target_keys (explicit zero-target liquidation), OR (b) tighten the
    compute_rebalance_plan docstring to assert/raise when
    holdings.keys() ⊄ target_weights.keys(), documenting the precondition.
    Option (a) is semantically correct per I3. Option (b) is acceptable if
    LivePortfolio semantics guarantee the sets match.

    Note: The spec does not restrict holdings.keys() to equal target_weights.keys(),
    so option (a) is the safer default.
