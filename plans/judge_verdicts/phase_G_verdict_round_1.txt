ADVISORY A-1: F-G2-03 AC-4 test coverage is partial [ADVISORY]
File: tests/test_portfolio.py — test_leaps_vix_creation_uses_raw_not_smoothed
-----------------------------------------------------------------------
AC-4 requires: "Contract-creation IV uses raw (unsmoothed) VIX while daily MTM
uses the 30-day rolling mean — the two paths are verifiably distinct when VIX is
volatile."

The test confirms creation uses raw VIX (day-1 contract premium matches flat-0.20
VIX run at line 750). However, no test explicitly verifies that daily MTM in the
backtest loop uses the smoothed 30-day series rather than raw VIX. The two-path
distinction (creation=raw, MTM=smoothed) is implemented correctly in portfolio.py
lines 289-290 vs 338-341, but the test only validates the creation path.

Recommended fix: Add a test that constructs a VIX spike scenario and verifies
that NAV on a date where smoothed ≠ raw VIX differs from a run using raw VIX
as the MTM input.

OBSERVATION: net_proceeds field in LeapsPartialCloseEvent is 0.0 [ADVISORY]
File: src/finance/portfolio.py lines 414
-----------------------------------------------------------------------
At the return boundary, partial close events are constructed with net_proceeds=0.0
(comment: "per-contract proceeds already booked to base at close time"). The
LeapsPartialCloseEvent docstring specifies net_proceeds as "Mark-to-market value
of the closed portion (no tax deduction)", implying the actual dollar amount.

The proceeds ARE correctly booked to base holdings during the loop (lines 381-387).
The 0.0 value in the event record means the ledger is not self-consistent for
post-hoc analytics (e.g., computing total proceeds from partial closes via the
ledger alone would yield 0). This is not tested by the spec, so no criterion is
UNMET. However, downstream analytics code consuming leaps_ledger.partial_close_events
would compute incorrect proceeds. Design judgment required: does the spec intend the
event to record the actual proceeds (making the ledger self-describing) or just
to mark that a close occurred?

Status: ESCALATION risk only if downstream analytics require accurate partial close
proceeds from the ledger. Noting as ADVISORY; flagging for human review.
