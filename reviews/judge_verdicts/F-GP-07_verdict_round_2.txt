[BLOCKING] LEAPS top-up elif branch is missing the glide-path guard — causes
  regression in non-glide-path DRIFT backtests
  File: src/finance/_backtest_steps.py, lines 1070-1075

  The new elif branch:
      elif leaps_value < target_leaps_now:
          shortage = target_leaps_now - leaps_value
          if ctx.base_assets:
              for a in ctx.base_assets:
                  holdings[a] -= shortage * base_target_norm.get(a, 0.0)
          leaps_value = target_leaps_now

  fires for ALL DRIFT portfolios, including non-glide-path ones. In the real-
  corpus I2 test (GTT+LEAPS+DRIFT, no glide_path_config), on specific month-ends
  where _should_rebalance fires and leaps_value < target_leaps_now (a natural
  condition when LEAPS contracts have been partially closed via GTT or decay),
  the branch incorrectly drains base holdings into LEAPS.

  Observed regression evidence:
    2010-05-28: residual=-75240.55,  expected=10000.00,  diff=-8.524e+04
    2022-05-31: residual=-263195.59, expected=10000.00,  diff=-2.732e+05
    2022-10-31: residual=-111354.35, expected=10000.00,  diff=-1.214e+05

  The spec acceptance criteria explicitly scopes this behavior:
    "LEAPS is topped up (not just trimmed) when its weight is below DYNAMIC
    TARGET by more than drift band"
  and:
    "Existing DRIFT and QUARTERLY test suite passes without modification."

  The fix is a one-line guard. The elif must check that dynamic_target_weights
  is active before topping up LEAPS:

      elif leaps_value < target_leaps_now and state.dynamic_target_weights is not None:

  This ensures the top-up only fires when the glide path is active and
  target_leaps_now was derived from dynamic_target_weights, not from ctx.w
  (which represents the fixed original weights in non-glide-path DRIFT).

[BLOCKING] test_leaps_topped_up_when_below_dynamic_target now correctly asserts
