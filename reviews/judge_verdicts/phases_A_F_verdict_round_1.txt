ADVISORY

A-1: figures.py format_performance_table omits skewness / excess_kurtosis
File: src/finance/figures.py lines 316, 340-348
-----------------------------------------------------------------------
_metrics_to_row() builds a 7-column row (ann_return through omega) and
format_performance_table assigns exactly 7 col_labels. The PerformanceMetrics
dataclass has 9 scalar fields — skewness and excess_kurtosis are silently dropped.
This is explicitly deferred to Sub-phase H ("Update format_performance_table to
include skewness, excess_kurtosis rows") and is therefore expected. No test
exercises these fields in the table output. The omission means the console report
is incomplete but does not produce incorrect output or test failures.

Recommended fix (Sub-phase H): add skewness and excess_kurtosis rows to
_metrics_to_row and extend col_labels accordingly. Add a test asserting both
field names appear in format_performance_table output.

A-2: data.py lines 300-301 and 306-311 lack unit test coverage [ADVISORY]
File: src/finance/data.py
-----------------------------------------------------------------------
Lines 300-301 (MUB dividend population inside if not mub_divs.empty) are skipped
because test_data.py mocks fetch_dividends to return an empty Series. The branch
where real dividends are reindexed and written is never executed.
Lines 306-311 (fetch_vol_indices=True path calling fetch_volatility_index) have
no test exercising the True branch; only the False branch (vol_prices = empty
DataFrame) is tested.
Both gaps are in the build_price_data I/O orchestrator, not in logic functions.
Network functions are correctly excluded via pragma: no cover.

Recommended fix: add two tests using mocked fetch_volatility_index and a non-empty
fetch_dividends return value to exercise these branches.

A-3: Pre-existing leverage.py coverage gaps (carried from Phase G verdict)
File: src/finance/leverage.py lines 389-390, 605-606
-----------------------------------------------------------------------
These gaps were documented in Phase G verdict A-3 and required actions items 1
and 2. They remain unresolved as of this survey. Reproducing here for completeness:
  - Lines 389-390: MIN_PREMIUM guard in create_leaps_contract — test inputs do not
    force premium below MIN_PREMIUM_PER_SHARE, so the guard branch is unreachable.
  - Lines 605-606: compute_leaps_mtm() is a public function with no tests and no
    callers in the production code path (dead code).
