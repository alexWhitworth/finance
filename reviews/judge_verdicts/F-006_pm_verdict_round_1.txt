FINDING 1 — ADVISORY: Spec gamma acceptance criterion contains a typo
  severity: ADVISORY
  file:     plans/portfolio_management_spec.json, line ~760
  detail:   Spec states gamma(100,100,1,0.20,0,0) ≈ 0.019894 within 1e-5.
            The correct analytic value is N'(0.1)/20 = 0.39695.../20 = 0.019848.
            |0.019848 - 0.019894| = 4.64e-05, which exceeds the stated 1e-5 tolerance.
            The implementation formula is correct; the spec oracle is wrong.
            Actor correctly computed the real value and updated the test to 0.019848.
  action:   Update spec acceptance criterion to 0.019848 within 1e-5 (or widen to 1e-4).

FINDING 2 — ADVISORY: Spec vega acceptance criterion is not the standard BS convention
  severity: ADVISORY
  file:     plans/portfolio_management_spec.json, line ~762
  detail:   Spec states vega ≈ 0.7954 within 1e-4 (per unit of vol).
            The standard BS vega formula S*exp(-qT)*N'(d1)*sqrt(T) yields 39.695 at
            these parameters — not 0.7954. The value 0.7954 corresponds to
            2*N'(d1)*sqrt(T) (dimensionless, without the S factor), which is not a
            textbook convention. Implementation is mathematically correct at 39.695.
  action:   Spec author should clarify the intended convention. If per-unit-IV-per-share
            (standard) is desired, the acceptance criterion should read ≈ 39.695 within
            1e-3. If per-1%-vol-point-per-share is desired, use 0.39695 within 1e-5.

FINDING 3 — BLOCKING: bs_call_charm is incorrect when dividend_yield != 0
  severity: BLOCKING
  file:     src/finance/leverage.py, lines 517-528
  detail:   The implementation computes charm as:
              charm_annual = -exp(-qT)*N'(d1)*numerator / (2T*sigma*sqrt(T))
            The correct formula for a dividend-paying underlying is:
              charm_annual = q*exp(-qT)*N(d1)
                             - exp(-qT)*N'(d1)*[2*(r-q)*T - d2*sigma*sqrt(T)]
                               / (2*T*sigma*sqrt(T))
            The missing term is: +q*exp(-qT)*N(d1)
            This term is derived from d/dT[exp(-qT)*N(d1)], specifically the
            -q*exp(-qT)*N(d1) part of the product-rule derivative.
            Negating for dDelta/dt convention gives: +q*exp(-qT)*N(d1).

            Bug is hidden at q=0 (the spec test case), because the missing term
            vanishes identically. All current tests pass q=0 exclusively.

            Magnitude of error at DEFAULT_DIVIDEND_YIELD (q=0.013):
              At S=K=100, T=1, σ=0.20, r=0.03:
                implementation:  -9.810e-05 /day
                correct value:   -7.794e-05 /day
                absolute error:   2.016e-05 /day  (~26% relative error)

            Independent derivation:
              Delta = exp(-qT)*N(d1)
              dDelta/dT = -q*exp(-qT)*N(d1) + exp(-qT)*N'(d1)*dd1/dT
              charm (dDelta/dt) = -dDelta/dT
                                 = q*exp(-qT)*N(d1) - exp(-qT)*N'(d1)*dd1/dT
              After substituting dd1/dT = [(r-q+0.5*sig^2)/(2*sig*sqrt(T))
                                           - log(S/K)/(2*sig*T^1.5)] this reduces to
              the formula above with the q*N(d1) term.

            Cross-check: from-scratch derivation matches standard formula to <1e-18;
            both disagree with implementation by ~2e-05/day when q=0.013.
  required: Add missing term to charm_annual in bs_call_charm.
            Add tests with q != 0 (e.g. DEFAULT_DIVIDEND_YIELD = 0.013).
