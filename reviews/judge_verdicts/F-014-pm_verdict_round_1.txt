[ADVISORY] data.py lines 293–298 — Branch 2 variable-name inversion in _fetch_ohlcv

  Context:
    Branch 2 is entered when raw.columns.names[0] == "Ticker", i.e. yfinance already
    returns (Ticker, Price) MultiIndex. The intent is to rename to ('ticker', 'field').
    The code reads:

        raw.columns = pd.MultiIndex.from_tuples(
            [(ticker, field) for field, ticker in raw.columns],   # line 295
            names=['ticker', 'field'],
        )

    Since raw.columns iteration yields (Ticker_val, Price_val) — e.g. ('VTI', 'Close') —
    the destructuring `for field, ticker in raw.columns` binds:
        field  = 'VTI'   (the ticker value)
        ticker = 'Close' (the price field value)
    Then the tuple (ticker, field) = ('Close', 'VTI').

    Result: columns are [('Close','VTI'), ('High','VTI'), ...] instead of
                        [('VTI','Close'), ('VTI','High'), ...].

    This is a BLOCKING logic error that would corrupt the (ticker, field) contract
    assumed by compute_leaps_dca_signal. It is only masked by the fact that the
    unit tests mock _fetch_ohlcv and never exercise this branch.

  Severity: Advisory (I/O boundary marked pragma: no cover; mocked in all tests).
            ESCALATES to BLOCKING if a live integration test is added for F-015 or F-016.

  Fix: swap the variable names in the destructuring:
        [(ticker, field) for ticker, field in raw.columns]

[ADVISORY] data.py lines 289–292 — Branch 1 stack produces wrong output shape

  Context:
    Branch 1 fires when raw.columns.names[0] != 'Ticker' (the standard yfinance >=0.2.x
    format, where names = ['Price', 'Ticker']).

        result = raw.stack(level=0, future_stack=True)
        result.columns.name = "field"
        return result

    stack(level=0) moves the Price axis into the row MultiIndex, producing:
        Index:   MultiIndex of (date, price_field)   — e.g. (2022-01-03, 'Close')
        Columns: flat Series of ticker names          — e.g. ['VTI']

    Setting columns.name = "field" renames the axis but leaves columns flat.
    The caller (compute_leaps_dca_signal) tests `isinstance(ohlcv.columns, pd.MultiIndex)`
    and expects (ticker, field) MultiIndex columns. The stacked result has no MultiIndex
    columns — downstream access of ohlcv['VTI']['High'] would silently fail or produce
    wrong data.

    The correct approach for this branch is swaplevel + rename:
        result = raw.swaplevel(axis=1)
        result.columns.names = ['ticker', 'field']

  Severity: Advisory (same pragma: no cover scope as above).
