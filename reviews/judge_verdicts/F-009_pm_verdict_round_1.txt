FINDINGS

[ADVISORY — A1] Mutable dict fields expose shallow mutability
  File: src/finance/portfolio_manager.py:44-45
  holdings: dict[str, float] and target_weights: dict[str, float] are mutable
  containers. frozen=True prevents reassignment of the reference but a caller
  can mutate lp.holdings["VTI"] = 0.0 in-place. DS-001 is marked immutable=true
  in the spec. No enforcement of deep immutability exists.
  Impact: Low — no production code path mutates these fields; the spec does not
  mandate MappingProxyType. Flagging for awareness only.
  Action: None required for PASS. If deep immutability is desired in a later
  pass, convert to types.MappingProxyType at construction.

[ADVISORY — A2] Tolerance-boundary mutation gap
  File: tests/test_portfolio_manager.py
  The `abs(total - 1.0) > 1e-6` tolerance is not tested at the exact boundary
  (sum = 1.0 ± 1e-6 exactly). Property tests cover [0.0, 0.5] which is safely
  out-of-range. A mutant changing 1e-6 → 1e-3 would still be caught, but a
  mutant changing `>` to `>=` would not be caught for the boundary value itself.
  The practical impact is negligible — no real portfolio weight can land exactly
  at machine-epsilon distance from 1.0 — but noted for completeness.
  Action: None required for PASS.
