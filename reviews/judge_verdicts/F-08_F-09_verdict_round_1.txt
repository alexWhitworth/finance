ADVISORY — A-01
File: src/finance/leverage.py:1033-1036
Category: Dead code (unreachable branch)
Detail: The ValueError guard after reindex uses mask_aligned.index.intersection(price_series.index),
but after `mask_aligned = position_mask.reindex(price_series.index, ...)`, mask_aligned.index IS
price_series.index by construction. The intersection is always non-empty as long as price_series
is non-empty (the empty case is already handled at line 1028). This branch can never fire.
The spec documents a raises-ValueError contract (API-SEGMENTED-LEAPS), but the current guard
does not test for the scenario it claims to test (misaligned foreign-index mask). No test
exercises line 1035 — it appears as an uncovered line in the coverage report.
Recommended fix: Replace with a check *before* reindex, e.g., test whether the raw
position_mask.index overlaps price_series.index when the mask is not empty, or remove the
guard and document that reindex handles misalignment by filling.

ADVISORY — A-02
File: tests/test_gtt_segmented_leaps.py — test_ldl_parked_pool_grows_through_defensive_window
Category: AC-2 BRITTLE assertion strength
Detail: F-09 AC-2 states: "reopens a fresh contract on the first re-entry day with capital ==
parked pool grown by defensive_gross_return over the defensive window (within 1e-9)." The test
only checks directionally that `len(second_long_contracts_with) > 0` and
`len(second_long_contracts_zero) > 0`. It does NOT compute the expected pool value and
compare re-entry contract sizing to it with 1e-9 tolerance. The spec's explicit precision
requirement is unverified.
Recommended fix: Manually compute expected pool = (close_proceeds) * prod(1 + daily_return)
over defensive dates, then assert the first second-Long n_contracts matches within 1e-9.

ADVISORY — A-03
File: src/finance/leverage.py:1097-1103 (lines 1098, 1102)
Category: Optional-series branches uncovered by F-09 tests
Detail: The true branches for `seg_iv` and `seg_rfr` inside the force-close block are only
reached when iv_series/risk_free_series are supplied to run_segmented_leaps_simulation. No
F-09 test passes these optional series. The logic is exercised indirectly via other tests
that pass iv_series/rfr to run_leaps_simulation, but the specific close-pricing path in
run_segmented_leaps_simulation is untested.
Recommended fix: Add one test that exercises run_segmented_leaps_simulation with an iv_series
and risk_free_series to cover lines 1098 and 1102.

ADVISORY — A-04
File: tests/test_gtt_segmented_leaps.py:49-73
Category: AC-1 BRITTLE assertion — "byte-equal" not enforced
Detail: The spec says "byte-equal (contracts, roll_events)". The test compares by
(purchase_date, strike, n_contracts) key-set equality and checks only len(roll_events).
It does not verify roll event content (old_contract, new_contract, roll date) or assert
contract tuple order. This could mask a bug where contracts exist with the same key but
different fields (e.g., different account_type or dividend_yield).
Recommended fix: Assert `seg_ledger.contracts == direct.contracts` directly since both
are frozen dataclasses in deterministic order, or at minimum assert roll event counts and
a key sample of roll fields.

ADVISORY — A-05
File: tests/test_gtt_leaps_close.py:76-80
Category: pytest.approx without explicit abs tolerance in round-trip test
Detail: Lines 77-80 use `pytest.approx(hardcoded_value)` (default 1e-6 relative). These are
for the dataclass round-trip test (not accounting math) so 1e-6 relative is fine; the values
are hardcoded, not computed. Low-severity advisory only.
