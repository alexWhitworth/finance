ADVISORY [A1] — "all contracts expired" edge case not directly tested via as_live_portfolio
  File: tests/test_portfolio_manager.py
  The spec edge case "all contracts in ledger are expired — returns empty leaps_contracts
  tuple" is not covered by a test that builds a ledger with only expired contracts and
  calls as_live_portfolio. The code relies on get_live_contracts to filter (correct), but
  a direct test would provide explicit regression protection.

ADVISORY [A2] — leaps_scale default=1.0 fallback: semantically sound but untested
  File: src/finance/portfolio_manager.py:105
  `state.leaps_scale.get(c, 1.0)` correctly assigns scale=1.0 to contracts not in
  leaps_scale (i.e. full position, not partially closed). Empirically verified: QUARTERLY
  backtest produces leaps_scale={} (all contracts at full scale), DRIFT produces non-empty
  leaps_scale. The fallback is correct but there is no test explicitly asserting the
  1.0-default path vs. the non-1.0 scale path in the same test.

ADVISORY [A3] — gtt_active=True with non-GTT backtest returns prev_regime=1
  File: src/finance/portfolio_manager.py:108
  When caller passes gtt_active=True on a non-GTT backtest, gtt_regime is set from
  state.prev_regime (which is 1 after any normal Long-only backtest). This is a
  caller-contract issue (gtt_active must match the backtest), not a defect. Docstring
  should explicitly warn callers that gtt_active=True on a non-GTT backtest produces
  a meaningless regime value.

ADVISORY [A4] — leaps_contracts tuple type vs. DS-001 spec type
  File: src/finance/portfolio_manager.py:46
  DS-001 specifies leaps_contracts type as `tuple[tuple[LeapsContract, float], ...]`.
  Implementation uses that exact type. The inner tuple is unnamed (not a NamedTuple).
  The spec does not require a NamedTuple, so this is conformant.
